## 1. Executive summary
Firefly wants to embed per-brand marketing-analytics dashboards and a natural-language
"ask your data" assistant inside its existing SaaS product, replacing a homegrown
Postgres+cron stack buckling at ~400 brands — without a year-long internal rebuild and
without ever exposing Databricks to a marketer.

This is a textbook **Built-On ISV (multi-tenant analytics)** pattern. The recommended design
stands Firefly's product on Databricks: Lakeflow ingestion + declarative medallion pipelines,
a Unity Catalog **Metric View** semantic layer (the hard prerequisite), embedded **AI/BI
dashboards** and **Genie** for conversational analytics, with **per-brand Service Principal +
UC row-level security** as the isolation model. Marketers authenticate through Firefly's own
IdP and never hold a Databricks identity.

**Headline effort:** ~4 phases (walking skeleton → single-tenant MVP → multi-tenant hardening
→ scale/GA); combined T-shirt **L**, dominated by Firefly-owned whitespace (app embed, SSO→SPN
broker, onboarding automation). **Headline cost:** LOW-confidence pending confirmed scale; the
key insight is that the serverless/pipeline **fixed floor dominates per-tenant cost at 400
brands and amortizes as brands grow** — pricing must clear today's floor, not the future one.
**Quality gate:** PASS (PWAF rubric 5/4/5 on the three non-negotiable dimensions).

## 5. Solution architecture (Databricks)
Lakeflow Connect (Postgres CDC) + Auto Loader → bronze; Lakeflow Declarative Pipelines →
silver/gold marts; **UC Metric Views** semantic layer; **AI/BI Dashboards** on DBSQL
Serverless + **Genie** for the assistant, both RLS-scoped per brand; Firefly's React shell
calls Genie + Statement Execution APIs via OAuth M2M to a **per-brand SPN**. Cross-cutting:
single UC metastore w/ shared-gold + RLS (D1), private networking (no browser→Databricks),
secrets in UC scopes, observability via system tables + MLflow traces.

## 6. Implementation roadmap, QA & evals
**P0** walking skeleton (one brand, one metric, one dashboard) → **P1** single-tenant MVP
(full marts + Genie) → **P2** multi-tenant hardening (RLS + per-brand SPN + onboarding;
**0-leak gate**) → **P3** scale/GA (embed, cost attribution, eval gate, SLA tuning). Test plan
maps every Stage-4 test to a Stage-2 criterion, with a **cross-tenant leakage suite** run in
CI across all brands. **Assistant eval** (MLflow scorers): Correctness ≥0.85, Groundedness
≥0.90, `no_cross_tenant`=1.0, Safety pass — below threshold blocks release.
*(Full plan in `04-roadmap.md`.)*
